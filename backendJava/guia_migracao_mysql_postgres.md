# Guia de Migração: MySQL para PostgreSQL

Este documento serve como referência técnica para o entendimento das diferenças entre os bancos de dados MySQL e PostgreSQL, além de documentar o processo prático de migração utilizando a ferramenta **pgloader** no ambiente Windows 11 direcionado ao Render.

---

## 1. Resumo Técnico: MySQL

O **MySQL** é um dos sistemas de gerenciamento de banco de dados relacionais (SGDBR) mais populares do mundo, amplamente conhecido por sua velocidade de leitura, simplicidade e forte adoção na web (integrando pilhas clássicas como LAMP/WAMP).

*   **Gerenciamento de Sequências:** Utiliza o atributo `AUTO_INCREMENT` diretamente na definição da coluna da chave primária.
*   **Tratamento de Booleanos:** Não possui um tipo booleano nativo real. Ele converte a palavra-chave `BOOLEAN` para o tipo numérico `TINYINT(1)`, armazenando os valores `0` (false) ou `1` (true).
*   **Case Sensitivity (Maiúsculas/Minúsculas):** Por padrão no Windows, os nomes de tabelas não diferenciam maiúsculas de minúsculas devido ao sistema de arquivos (NTFS). No Linux, o comportamento padrão diferencia.
*   **Mecanismos de Armazenamento:** Utiliza motores modulares, sendo o **InnoDB** o padrão moderno devido ao suporte a transações ACID e chaves estrangeiras.

---

## 2. Resumo Técnico: PostgreSQL

O **PostgreSQL** é um banco de dados relacional e objeto-relacional de código aberto, focado em extensibilidade, robustez técnica e conformidade estrita com os padrões ANSI SQL. É amplamente escolhido para sistemas complexos que exigem alta integridade de dados.

*   **Gerenciamento de Sequências:** Utiliza objetos independentes chamados *Sequences*. Na prática, implementa-se através dos tipos `SERIAL` (atalho para criar uma sequência associada) ou a sintaxe moderna padrão ANSI `GENERATED BY DEFAULT AS IDENTITY`.
*   **Tratamento de Booleanos:** Possui suporte nativo e estrito ao tipo `BOOLEAN`, aceitando e validando apenas estados lógicos reais (`true` ou `false`).
*   **Case Sensitivity (Maiúsculas/Minúsculas):** É estritamente *case-sensitive* para identificadores não entre ASPAS duplas. Se você criar uma tabela chamada `Usuarios`, o Postgres criará internamente como `usuarios` (tudo minúsculo). Buscar por `SELECT * FROM "Usuarios"` falhará se a tabela tiver sido criada sem aspas.
*   **Recursos Avançados:** Suporte nativo avançado para indexação e manipulação de arquivos semiestruturados através do tipo **JSONB**, além de tipos geométricos, geográficos (PostGIS) e concorrência MVCC robusta.

---

## 3. Tabela Comparativa de Recursos

| Recurso / Atributo | MySQL | PostgreSQL |
| :--- | :--- | :--- |
| **Padrão SQL** | Focado em pragmatismo/velocidade | Conformidade estrita (ANSI SQL) |
| **Chave Primária Sequencial** | `AUTO_INCREMENT` | `SERIAL` ou `IDENTITY` |
| **Tipo Booleano** | `TINYINT(1)` (0 ou 1) | `BOOLEAN` (`true` ou `false`) |
| **Identificadores (Nomes)** | Case-insensitive (no Windows) | Case-sensitive (Geralmente lowercase) |
| **Suporte Semi-estruturado** | Limitado (JSON básico) | Excelente (JSONB indexável) |

## 4. Manual de Migração Prática (Windows 11)

Abaixo estão os passos validados para extrair os dados e o esquema do seu banco de dados MySQL local e injetá-los no PostgreSQL hospedado no Render utilizando a versão universal em Java do **pgloader**.

### Passo 1: Pré-requisitos do Sistema
1. Certifique-se de ter o **Java 21** ou superior instalado no seu Windows 11.
2. Verifique abrindo o PowerShell ou Prompt de Comando e digitando:
   ```bash
   java -version
   ```

### Passo 2: Preparação do Ambiente e Executável
1. Baixe o arquivo binário estável pré-compilado através do seu navegador:
   * [Download pgloader.jar (GitHub)](https://github.com/dimitri/pgloader/releases/download/v4-dev/pgloader.jar)
2. Crie uma pasta dedicada para o processo no seu disco (Exemplo: `C:\migracao`).
3. Mova o arquivo `pgloader.jar` baixado para dentro desta pasta criada.

### Passo 3: Executando o Comando de Migração
Abra o terminal do Windows, navegue até a pasta de migração e execute a instrução estruturada de conexão. O utilitário irá ler o banco de origem, converter os tipos incompatíveis automaticamente em memória e popular a nuvem.

```bash
cd C:\migracao

java -jar pgloader.jar mysql://root:SUA_SENHA_LOCAL@localhost:3306/SEU_BANCO_ORIGEM postgres://usuario_render:senha_render@host_render.render.com/nome_banco_destino
```

> **Aviso de Segurança:** Substitua os blocos em maiúsculo com suas credenciais vigentes. Não compartilhe a string final publicamente devido à exposição de tokens de autenticação administrativa.
